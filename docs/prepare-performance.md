# Fusing plain INT8 preparation

`prepare_plain_i8` rotates each MLP activation row with a group-256 Hadamard
transform before computing the row scale and quantizing to INT8. Previously it
copied the input to LDS, then ran four separate radix-4 stages through LDS.

Each lane now loads 16 adjacent FP16 values and performs the first two stages
in registers. Both stages still calculate in FP32 and round their results to
FP16. The second stage's results go to LDS for the remaining cross-lane stages.
This removes two whole-row LDS writes, two whole-row LDS reads and two workgroup
barriers. It changes neither the transform nor the quantizer. Widths with a
2048-element tail use half of the final workgroup iteration; every lane still
reaches the following barrier.

## Measurements

On Radeon 8060S / gfx1151, 2026-09-28, using `hrx-rs` 0.8.11 and its pinned
Loom compiler, width 16384, FP16 input and INT8 output:

| Tokens | Before (ms) | After (ms) | Latency reduction |
| ---: | ---: | ---: | ---: |
| 1043 | 0.297966 | 0.250215 | 16.0% |
| 4115 | 1.113997 | 0.956457 | 14.1% |
| 9235 | 2.456507 | 2.110029 | 14.1% |

Each row pools two comparisons with reversed source order, each with 51 measured
rounds of five dispatches: 510 dispatch timings per arm. Both comparisons showed
an improvement at every size. The GPU was shared with an active application, and
model loading also ran on the host. These results demonstrate a kernel improvement
under those conditions; they do not establish idle-machine latency or a measurable
whole-image speedup. The [raw record](benchmarks/prepare-fusion-2026-09-28.json)
contains every sample, compiler identity, resource reports and source hashes.

An additional reduction-scratch reuse experiment raised reported occupancy from
37% to 50%, but did not consistently beat fusion alone in longer interleaved runs,
so the production change retains the original reduction.

## Reproduction

The benchmark checks all quantized bytes, scale bits and output padding before
timing and again after repeated graph replay. Inputs contain positive and negative
finite FP16 values, subnormals and zero rows. Each arm has two warm-up rounds,
followed by alternating measured rounds of five dependent dispatches. HRX's GPU-clock timestamps exclude
compilation, allocation, uploads and downloads. JSON output retains every sample
and compiled artifact path.

```sh
git show 470f60c:kernels/prepare_plain_i8.loom > /tmp/prepare-before.loom
cargo run --release --example prepare_ab -- 4115 16384 51 \
  /tmp/prepare-before.loom kernels/prepare_plain_i8.loom
```

Reverse the two source arguments to check order sensitivity. Width 16384 is the
production MLP shape; 1043, 4115 and 9235 tokens represent three image sizes with
19 text tokens. These are isolated preparation timings, not whole-image speedups.

## Correctness

`plain_preparation_preserves_each_half_rounding_boundary` checks exact scale and
quantized output bits against independent CPU 4x4 matrix products with an FP16
round after each radix. It covers widths 2048, 6144 and 16384, including zero and
subnormal rows and untouched padding. The existing Kronecker-product test also
checks preparation against the complete mathematical transform.

CPU checks and both GPU oracles passed. Original and optimized builds also
produced byte-identical 1024x1024 RGB for the complete two-step pipeline at seed
37, prompt `a red ceramic cup on a wooden table`. Each build repeated the request
three times after warm-up, with identical RGB and no growth in tracked warm
allocations or reserved memory. The raw record includes these diagnostic timings,
but they are not a controlled end-to-end speed comparison.

```sh
cargo test --release --test quantized preparation -- --ignored --nocapture
scripts/parity.sh
```

The parity gate uses the frozen unquantized BF16 trajectory and decoded image;
its baseline is not regenerated by this optimization. The full eight-step gate
passed: relative latent RMS 0.076912 and image PSNR 31.777828 dB, with 0.000000 dB
latent regression and unchanged image PSNR against the accepted baseline.
